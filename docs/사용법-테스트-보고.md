# signus 사용·테스트 설명서

무엇을 하는 물건인지는 `README.md`. 이 문서는 **어떻게 돌리고, 어떻게 테스트하고, 실신호에서
이상한 결과가 나왔을 때 그걸 어떤 형식으로 넘길지**만 다룬다.

이 문서의 모든 출력 예시는 실제로 돌려서 붙인 것이다. 지어낸 화면은 없다.

---

## 1. 설치

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev,tools]'    # 본체 + 테스트(pytest,ruff) + 인쇄물 발급기(pygments)
```

| extra | 내용 | 언제 |
|---|---|---|
| (없음) | numpy, scipy 뿐 | 분석만 할 때 |
| `dev` | pytest, ruff | 코드를 고칠 때 |
| `tools` | pygments | 필사 인쇄물을 뽑을 때 |
| `fast` | numba | 등화기/반송파 루프 16~34배. 없으면 같은 결과의 순수 numpy로 폴백 |

`.venv/bin/pip install -e .` 를 하면 `signus` 명령이 등록된다. 안 하고 쓰려면 아래 모든 예시의
`signus` 를 `.venv/bin/python -m signus.cli` 로 바꿔 읽으면 된다.

ssh 보드에서도 같다. 인쇄물까지 뽑으려면 `apt install chromium` 이 추가로 필요하다
(헤드리스 크롬이 PDF를 그린다. 못 찾으면 `CHROME=/usr/bin/chromium` 으로 지정).

## 2. 파일을 넣기 전에 — "읽기 필수 정보"

분석기는 파일을 열기 위해 **fs(샘플레이트)** 와 **fmt(iq/real)** 를 반드시 알아야 한다.
이건 물리적으로 추정 불가능한 정보라서 반드시 밖에서 준다. 세 경로가 있고, 아래가 위를 이긴다:

1. 파일명 토큰
2. `<확장자뺀이름>.sigmf-meta` (SigMF)
3. CLI 플래그 (`--fs --fmt --dtype --be --bitrev --rf`)

### 파일명 토큰

```
<라벨>_fs<샘플레이트>_<iq|real>_<샘플타입>[_be][_bitrev][_rf<Hz>].<iq|pcm>
예: capture_fs2000000_iq_i16.iq
    voice_fs48000_real_f32_rf433920000.pcm
```

- **샘플타입**: `i8` `u8` `i16` `u16` `f32` `f64` (기본 `i16`).
  별칭도 인식: `8t`→i8 `8o`→u8 `16t`→i16 `16o`→u16 `32f`→f32 `64f`→f64 (baudline 표기).
- `be` = 빅엔디안, `bitrev` = 바이트 안에서 비트 역순.
- `rf<Hz>` 를 주면 기저대역 fc 가 아니라 **실제 RF 주파수**로도 보고한다.

토큰이 없으면 이렇게 죽는다 (친절한 메시지가 아니라 그냥 예외다):

```
ValueError: need fs + fmt (filename tokens, SigMF, or --fs/--fmt): /tmp/nofs.iq
```

→ 파일명을 고치거나 `--fs 2e6 --fmt iq` 를 붙인다.

### 정답 사이드카는 채점용이지 탐지용이 아니다

`<파일>.json` 에 변조·fc·baud 가 들어 있어도 **분석기는 절대 읽지 않는다.** 화면 오른쪽에
`(정답 16qam)` 처럼 비교 표시만 된다. 실신호에 정답을 아는 채로 넣어도 결과는 블라인드다.

## 3. 명령어

### `analyze` — 단일 신호

```bash
signus analyze samples/16qam_fs1000000_iq_i16.iq
```
```
모드      16qam   (정답 16qam)
반송파    8000.1 Hz   (정답 8000.0)
심볼레이트 100000.1 Hz   (정답 100000.0)
롤오프    0.33   lock 100.0   MER 29.8 dB
```

| 옵션 | 뜻 |
|---|---|
| `--fs --fmt --dtype --be --bitrev` | 읽기 정보 강제 (파일명/SigMF 를 덮는다) |
| `--rf <Hz>` | 캡처 중심 RF. 주면 `실제 RF` 줄이 추가된다 |
| `--burst N` | 버스트를 골라 분석 (1부터. 기본은 가장 센 버스트) |
| `--diff` | 차동 디맵 (D-BPSK/D-QPSK/π4-DQPSK 는 성상도가 부모와 같아 이 플래그로 구분) |
| `--report out.json` | 전체 리포트 저장 (성상도·비트·스펙트럼 포함, 수백 KB) |
| `--save-iq / --save-symbols / --save-bits [--packed]` | 중간 산출물 저장 |

**출력 읽는 법**

- `lock` (0~100) — 성상도가 얼마나 조밀·정렬됐나. **60 이상이면 복조를 믿을 만하다.**
  0 근처면 복조가 아니라 **읽기 설정(dtype/fs)을 먼저 의심한다** (§6).
- `MER` 높을수록 깨끗, `EVM` 낮을수록 좋음.
- 아래 줄들은 조건부로만 뜬다:
  - `버스트 N개 감지 — k번째 분석` → `--burst` 로 나머지도 본다
  - `등화기 적용` → 다중경로 ISI 보정됨 (심볼간격 / T/2 분수간격)
  - `반송파 앨리어스 보정` → fc 후보 중 스펙트럼 중심에 가까운 것을 골랐다
  - `심볼레이트 폴백` → 저 롤오프라 점유대역폭 사전정보로 재탐색했다
  - `경고: 반송파 앨리어싱 가능` → fc 를 그대로 믿지 말 것

### `survey` — 광대역 캡처 (여러 신호가 한 파일에)

```bash
signus survey capture_fs20000000_iq_i16.iq
```
```
4개 신호 감지 (샘플레이트 20000000 Hz)
 #        중심주파수        대역폭      분류      변조       심볼레이트  lock
 0   -6.200 MHz +234.38 kHz     디지털    qpsk      200000    93
 1   -1.500 MHz +468.75 kHz     디지털   16qam      400000   100
 2   +3.100 MHz +180.66 kHz     FSK     msk      150000   100
 3   +7.400 MHz +346.68 kHz     디지털    8psk      300000    93
```
(위 출력은 QPSK·16QAM·2FSK·8PSK 를 20 MHz 폭에 합성해 넣은 캡처를 실제로 돌린 것이다.
`samples/` 는 git 에 올라가지 않으므로 같은 파일이 clone 에는 없다 — `signus gen` 으로 만든다.
h=0.5 인 2FSK 는 정의상 MSK 라서 `msk` 로 나오는 게 맞다.)

`분류` 는 디지털 / FSK / 아날로그 / 순수톤 / 처프. **아날로그·톤·처프는 성상도에 억지로 맞추지
않고 그대로 보고한다** — 이건 실패가 아니라 설계다. `--rf` 를 주면 중심주파수 칸이 실제 RF 가 된다.
`--report out.json` 은 여기서도 쓸 수 있고, analyze 와 달리 가벼운 JSON 이다.

### `serve` — 웹 UI

```bash
signus serve                      # http://127.0.0.1:8000
signus serve --host 0.0.0.0 --port 8125
```

파일을 끌어다 놓으면 애니메이션 성상도·워터폴·일괄 분석. 보드에서 띄우고 맥 브라우저로 볼 거면
`--host 0.0.0.0` 이 필요하다(또는 `ssh -L 8000:localhost:8000 보드`). CDN 요청이 0이라 격리망에서
그대로 돈다.

### `gen` / `dataset` — 합성 신호 (재현용)

```bash
signus dataset --out samples          # 변조×샘플타입×장애 30종 + 정답 사이드카
signus gen --mod qpsk --snr 8 --taps 1,0,0.35j --out samples --label myecho
```

`gen` 주요 옵션: `--mod --fs --baud --snr --rolloff --cfo --phase --timing --pad --drift-ppm
--dc --h(FSK 변조지수) --taps(멀티패스) --fmt --dtype --be --bitrev --n --seed`.

**이게 실신호 디버깅의 핵심 도구다.** 실신호에서 본 실패를 `gen` 으로 재현할 수 있으면 그때부터
테스트로 잠글 수 있다.

### `sweep` — 전수조사 (수용 시험)

```bash
signus sweep --tier core     # CORE 는 100% 통과가 필수. 하나라도 깨지면 종료코드 1
signus sweep --tier full     # + STRETCH (저SNR·큰CFO·드리프트 등, 보고만)
```

케이스마다 이렇게 찍는다:

```
[PASS] CORE    qpsk/r10/s0        qpsk fc    0.0 baud 0.00% roll0.35 lock 92.9 ber0.0000
[PASS] CORE    qpsk/alias         qpsk fc    0.0 baud 0.00% roll0.33 lock 93.2 ber0.0000
CORE: 30/30 pass
```

변조·fc·baud·롤오프·lock 에 더해 **CORE 는 BER 까지 0 이어야** 통과다.

## 4. 테스트

```bash
.venv/bin/python -m pytest -q          # 단위·회귀 테스트 (413개)
.venv/bin/python -m ruff check .       # line-length 100
signus sweep --tier core               # 종단 수용 시험
```

**세 개가 다 통과해야 커밋이다.** 순서도 이게 맞다 — pytest 가 제일 빠르고 실패 지점이 좁다.

깨졌을 때:

1. `pytest -q -x` 로 첫 실패에서 멈춘다.
2. 그 테스트가 잠그고 있는 **실패 시나리오**를 먼저 읽는다 (이 저장소의 테스트는 대부분
   "예전에 이렇게 조용히 틀렸다"는 기록이다).
3. 고친 뒤 `sweep --tier core` 로 정상 신호가 안 깨졌는지 본다.

## 5. 실신호 결과를 넘기는 형식

실신호에서 이상하면 **`tools/report.sh` 가 만든 덩어리를 그대로 붙여넣으면 된다.**

```bash
tools/report.sh analyze caps/capture_fs2000000_iq_i16.iq
tools/report.sh survey  caps/wide_fs20000000_iq_i16.iq --rf 433.92e6
tools/report.sh analyze caps/burst_fs2000000_iq_i16.iq --burst 3 > /tmp/report.txt
```

나오는 형식:

```
=== signus 실신호 리포트 ===
파일   16qam_fs1000000_iq_i16.iq  ·  236K  ·  sha256 e79d5accdac2
사이드카 16qam_fs1000000_iq_i16.iq.json 있음 (분석기는 안 읽음 · 비교 표시용)
명령   signus analyze samples/16qam_fs1000000_iq_i16.iq
리비전 ee2ee6d +미커밋1개
환경   Darwin 25.5.0 · py3.13 numpy2.5.1 scipy1.18.0

--- 출력 ---
(터미널 출력 그대로)

--- 요약 (배열 제거) ---
{ "fs": ..., "detected": {...}, "quality": {...}, "burst": {...} }

--- 내가 본 것 (직접 채워주세요) ---
기대:
실제:
근거:
파일 전달 가능: 예 / 아니오
```

**왜 이 형식인가**

- `--report` JSON 원본은 270KB다 (성상도·비트·스펙트럼·워터폴 배열). 붙여넣을 수 없고,
  진단에 쓰이는 건 `detected` / `quality` / `burst` / `eq` 뿐이라 스크립트가 배열을 걷어낸다.
- **리비전과 환경**이 없으면 재현이 안 된다. `+미커밋N개` 가 붙어 있으면 그 코드는 원격에
  없다는 뜻이라, 그것부터 받아야 한다.
- **sha256 앞 12자**로 "그때 그 파일"인지 확인한다. 같은 이름 다른 캡처가 제일 흔한 혼선이다.
- **`내가 본 것` 세 줄이 제일 중요하다.** 출력만 있으면 그게 틀렸다는 걸 알 방법이 없다.
  "8PSK 로 나왔는데 이 링크는 QPSK 인 걸 알고 있다"가 있어야 수사가 시작된다.

**증상별로 같이 주면 좋은 것**

| 증상 | 추가로 필요한 것 |
|---|---|
| lock 은 높은데 변조가 틀렸다 | 웹 UI 성상도 스크린샷 (모양이 답을 반쯤 준다) |
| lock 이 0~30 | `--dtype` 을 바꿔가며 돌린 결과 2~3개 (§6) |
| survey 가 신호를 놓쳤다 / 없는 걸 만들었다 | 웹 UI 워터폴 스크린샷 + 안다면 그 신호의 대략 주파수·대역폭 |
| 심볼레이트만 배수로 틀렸다 | `--report` 요약의 `baud_conf` 값 (라인 신뢰도) |
| 짧은 패킷이 통째로 안 잡힌다 | 대략의 버스트 길이(샘플 수)와 반복 주기 |
| 크래시 | 트레이스백 전체 (요약하지 말고 그대로) |

**파일을 못 줄 때**: 대신 ① 위 리포트, ② 성상도·워터폴 스크린샷, ③ 아는 제원(대역폭·심볼레이트·
변조 후보)을 준다. 이 셋이면 대개 `signus gen` 으로 비슷한 신호를 만들어 재현을 시도할 수 있다.

**받으면 하는 일**: 합성으로 재현 → 재현되면 `tests/` 에 잠그고 고친다 → `pytest` + `sweep --tier
core` 로 정상 신호가 안 깨졌는지 확인. 재현이 안 되면 그 사실을 먼저 말하고 파일이나 추가 정보를
요청한다. **재현 없이 추측으로 고치지 않는다** — 이 저장소가 반복해서 당한 게 "확신에 찬 오답"이다.

## 6. 자주 막히는 곳

**lock 이 0 근처, MER 이 음수, 롤오프가 1.00** → 거의 항상 **샘플타입이 틀렸다.** i16 파일을
f32 로 읽으면 이렇게 된다:

```
모드      qpsk   (정답 16qam)
반송파    -249999.8 Hz   (정답 8000.0)
심볼레이트 104605.5 Hz   (정답 100000.0)
롤오프    1.00   lock 0.0   MER -0.9 dB
```

`--dtype i16 / f32 / i8 / u8` 을 차례로 넣어보고 lock 이 뛰는 걸 고른다. 엔디안(`--be`)과
`--bitrev` 도 같은 방식으로 확인한다.

**`need fs + fmt`** → §2. 파일명 토큰이나 `--fs/--fmt`.

**변조는 맞는데 fc 가 이상하다** → `경고: 반송파 앨리어싱 가능` 이 같이 떴는지 본다. M제곱 톤은
fs 모듈로 랩되므로 fc 는 원리적으로 fs/sym 모듈로만 결정된다. 비트는 대개 멀쩡하다.

**π/4-DQPSK 를 QPSK 로 부른다** → 설계된 동작이다. fc 가 `baud/8` 밀리지만 `--diff` 로 비트는
정확히 나온다(BER 0).

**아날로그/톤/처프로 분류됐다** → 실패가 아니라 거부다. 이것들을 성상도에 맞추면 조용한 오답이
나오기 때문에 일부러 안 한다.

**보드에서 인쇄물이 안 나온다** → 헤드리스 크롬이 없다. `apt install chromium` 하거나
`CHROME=/usr/bin/chromium .venv/bin/python tools/codebook.py all`.
