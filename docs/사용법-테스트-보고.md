# signus 사용·테스트 설명서

무엇을 하는 물건인지는 `README.md`. 이 문서는 **어떻게 돌리고, 어떻게 테스트하고, 실신호에서
이상한 결과가 나왔을 때 그걸 어떤 형식으로 넘길지**만 다룬다.

이 문서의 모든 출력 예시는 실제로 돌려서 붙인 것이다. 지어낸 화면은 없다.

---

## 1. 설치

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev,tools]'    # 본체 + 테스트(pytest,ruff) + 인쇄물 발급기(pygments)
```

| extra | 내용 | 언제 |
|---|---|---|
| (없음) | numpy, scipy 뿐 | 분석만 할 때 |
| `dev` | pytest, ruff | 코드를 고칠 때 |
| `tools` | pygments | 필사 인쇄물을 뽑을 때 |
| `fast` | numba | 등화기/반송파 루프 16~34배. 없으면 같은 결과의 순수 numpy로 폴백 |

`.venv/bin/pip install -e .` 를 하면 `signus` 명령이 등록된다. 안 하고 쓰려면 아래 모든 예시의
`signus` 를 `.venv/bin/python -m signus.cli` 로 바꿔 읽으면 된다.

ssh 보드에서도 같다. 인쇄물까지 뽑으려면 `apt install chromium` 이 추가로 필요하다
(헤드리스 크롬이 PDF를 그린다. 못 찾으면 `CHROME=/usr/bin/chromium` 으로 지정).

## 2. 파일을 넣기 전에 — "읽기 필수 정보"

분석기는 파일을 열기 위해 **fs(샘플레이트)** 와 **fmt(iq/real)** 를 반드시 알아야 한다.
이건 물리적으로 추정 불가능한 정보라서 반드시 밖에서 준다. 세 경로가 있고, 아래가 위를 이긴다:

1. 파일명 토큰
2. `<확장자뺀이름>.sigmf-meta` (SigMF)
3. CLI 플래그 (`--fs --fmt --dtype --be --bitrev --rf`)

### 파일명 토막 — 점으로 끊고 `.pcm` 으로 끝낸다

```
<이름>.<cplx|real>.<샘플레이트 정수>.<샘플타입>[.be][.bitrev][.rf<Hz>].pcm

예: capture.cplx.2000000.16t.pcm
    voice.real.48000.32f.rf433920000.pcm
```

- **`cplx`** = 복소(I/Q 교대), **`real`** = 실수 통과대역. 둘 다 확장자는 `.pcm` 이다.
- **샘플레이트는 접두사 없이 포맷 바로 다음 자리.** 그래서 이름이 숫자여도
  (`20260801.cplx.1000000.16t.pcm`) 안 헷갈리고, 이름에 `real` 이 들어가도
  (`my_real.cplx.…`) 샘플레이트를 데리고 다니는 쪽이 진짜 포맷으로 뽑힌다.
- **샘플타입**: `16t`→i16 `8t`→i8 `8o`→u8 `16o`→u16 `32f`→f32 `64f`→f64 (baudline 표기).
  `i16` `f32` 같은 내부 이름으로 써도 읽는다. 없으면 `16t` 로 친다.
- `be` = 빅엔디안, `bitrev` = 바이트 안에서 비트 역순. `rf<Hz>` 를 주면 기저대역 fc 가 아니라
  **실제 RF 주파수**로도 보고한다.

**옛 밑줄 형식(`cap_fs1000000_iq_i16.iq`)도 계속 읽는다** — 이미 받아둔 캡처를 안 고쳐도 된다.
다만 `signus gen`/`dataset` 이 **저장할 때는 새 형식만** 쓴다.

토막이 없으면 이렇게 죽는다 (친절한 메시지가 아니라 그냥 예외다):

```
ValueError: need fs + fmt (filename tokens, SigMF, or --fs/--fmt): /tmp/nofs.bin
```

→ 파일명을 고치거나 `--fs 2e6 --fmt iq` 를 붙인다. (플래그 이름은 그대로 `iq` 다 — 내부
어휘와 `--dtype i16` 표기는 바뀌지 않았고, 파일명 표기만 `cplx`/`16t` 다.)

### 정답 사이드카는 채점용이지 탐지용이 아니다

`<파일>.json` 에 변조·fc·baud 가 들어 있어도 **분석기는 절대 읽지 않는다.** 화면 오른쪽에
`(정답 16qam)` 처럼 비교 표시만 된다. 실신호에 정답을 아는 채로 넣어도 결과는 블라인드다.

## 3. 명령어

### `analyze` — 단일 신호

```bash
signus analyze samples/16qam.cplx.1000000.16t.pcm
```
```
모드      16qam   (정답 16qam)
반송파    8000.1 Hz   (정답 8000.0)
심볼레이트 100000.1 Hz   (정답 100000.0)
롤오프    0.33   lock 100.0   MER 29.8 dB
```

| 옵션 | 뜻 |
|---|---|
| `--fs --fmt --dtype --be --bitrev` | 읽기 정보 강제 (파일명/SigMF 를 덮는다) |
| `--rf <Hz>` | 캡처 중심 RF. 주면 `실제 RF` 줄이 추가된다 |
| `--burst N` | 버스트를 골라 분석 (1부터. 기본은 가장 센 버스트) |
| `--diff` | 차동 디맵 (D-BPSK/D-QPSK/π4-DQPSK 는 성상도가 부모와 같아 이 플래그로 구분) |
| `--report out.json` | 전체 리포트 저장 (성상도·비트·스펙트럼 포함, 수백 KB) |
| `--save-iq / --save-symbols / --save-bits [--packed]` | 중간 산출물 저장 |

**출력 읽는 법**

- `lock` (0~100) — 성상도가 얼마나 조밀·정렬됐나. **60 이상이면 복조를 믿을 만하다.**
  0 근처면 복조가 아니라 **읽기 설정(dtype/fs)을 먼저 의심한다** (§6).
- `MER` 높을수록 깨끗, `EVM` 낮을수록 좋음.
- 아래 줄들은 조건부로만 뜬다:
  - `버스트 N개 감지 — k번째 분석` → `--burst` 로 나머지도 본다
  - `등화기 적용` → 다중경로 ISI 보정됨 (심볼간격 / T/2 분수간격)
  - `반송파 앨리어스 보정` → fc 후보 중 스펙트럼 중심에 가까운 것을 골랐다
  - `심볼레이트 폴백` → 저 롤오프라 점유대역폭 사전정보로 재탐색했다
  - `경고: 반송파 앨리어싱 가능` → fc 를 그대로 믿지 말 것

### `survey` — 광대역 캡처 (여러 신호가 한 파일에)

```bash
signus survey capture.cplx.20000000.16t.pcm
```
```
4개 신호 감지 (샘플레이트 20000000 Hz)
 #        중심주파수        대역폭      분류      변조       심볼레이트  lock
 0   -6.200 MHz +234.38 kHz     디지털    qpsk      200000    93
 1   -1.500 MHz +468.75 kHz     디지털   16qam      400000   100
 2   +3.100 MHz +180.66 kHz     FSK     msk      150000   100
 3   +7.400 MHz +346.68 kHz     디지털    8psk      300000    93
```
(위 출력은 QPSK·16QAM·2FSK·8PSK 를 20 MHz 폭에 합성해 넣은 캡처를 실제로 돌린 것이다.
`samples/` 는 git 에 올라가지 않으므로 같은 파일이 clone 에는 없다 — `signus gen` 으로 만든다.
h=0.5 인 2FSK 는 정의상 MSK 라서 `msk` 로 나오는 게 맞다.)

`분류` 는 디지털 / FSK / 아날로그 / 순수톤 / 처프. **아날로그·톤·처프는 성상도에 억지로 맞추지
않고 그대로 보고한다** — 이건 실패가 아니라 설계다. `--rf` 를 주면 중심주파수 칸이 실제 RF 가 된다.
`--report out.json` 은 여기서도 쓸 수 있고, analyze 와 달리 가벼운 JSON 이다.

### `serve` — 웹 UI

```bash
signus serve                      # http://127.0.0.1:8000
signus serve --host 0.0.0.0 --port 8125
```

파일을 끌어다 놓으면 애니메이션 성상도·워터폴·일괄 분석. 보드에서 띄우고 맥 브라우저로 볼 거면
`--host 0.0.0.0` 이 필요하다(또는 `ssh -L 8000:localhost:8000 보드`). CDN 요청이 0이라 격리망에서
그대로 돈다.

### `gen` / `dataset` — 합성 신호 (재현용)

```bash
signus dataset --out samples          # 변조×샘플타입×장애 30종 + 정답 사이드카
signus gen --mod qpsk --snr 8 --taps 1,0,0.35j --out samples --label myecho
```

`gen` 주요 옵션: `--mod --fs --baud --snr --rolloff --cfo --phase --timing --pad --drift-ppm
--dc --h(FSK 변조지수) --taps(멀티패스) --fmt --dtype --be --bitrev --n --seed`.

**이게 실신호 디버깅의 핵심 도구다.** 실신호에서 본 실패를 `gen` 으로 재현할 수 있으면 그때부터
테스트로 잠글 수 있다.

### `sweep` — 전수조사 (수용 시험)

```bash
signus sweep --tier core     # CORE 는 100% 통과가 필수. 하나라도 깨지면 종료코드 1
signus sweep --tier full     # + STRETCH (저SNR·큰CFO·드리프트 등, 보고만)
```

케이스마다 이렇게 찍는다:

```
[PASS] CORE    qpsk/r10/s0        qpsk fc    0.0 baud 0.00% roll0.35 lock 92.9 ber0.0000
[PASS] CORE    qpsk/alias         qpsk fc    0.0 baud 0.00% roll0.33 lock 93.2 ber0.0000
CORE: 30/30 pass
```

변조·fc·baud·롤오프·lock 에 더해 **CORE 는 BER 까지 0 이어야** 통과다.

## 4. 테스트

```bash
.venv/bin/python -m pytest -q          # 단위·회귀 테스트 (442개)
.venv/bin/python -m ruff check .       # line-length 100
signus sweep --tier core               # 종단 수용 시험
```

**세 개가 다 통과해야 커밋이다.** 순서도 이게 맞다 — pytest 가 제일 빠르고 실패 지점이 좁다.
단 이건 **개발기(맥·ssh 보드) 규칙**이다. 격리망 장비에는 `tests/` 도 `dev` extra 도 없다
(테스트 코드는 인쇄물에서 영구 제외). 거기서 가능한 검증은 `signus sweep --tier core` 뿐이다.

깨졌을 때:

1. `pytest -q -x` 로 첫 실패에서 멈춘다.
2. 그 테스트가 잠그고 있는 **실패 시나리오**를 먼저 읽는다 (이 저장소의 테스트는 대부분
   "예전에 이렇게 조용히 틀렸다"는 기록이다).
3. 고친 뒤 `sweep --tier core` 로 정상 신호가 안 깨졌는지 본다.

## 5. 실신호 결과를 넘기는 형식

**손으로 받아쳐야 하는 상황이 기본이다** (격리망 장비 — 인터넷도 클립보드도 없다). 그래서
형식은 필사용 코드북과 같은 원칙으로 만든다: 짧게, 헷갈리는 글자를 피하고, **틀리면 티가 나게.**

> **발행기는 `signus` 안에 있다.** 그 장비에는 `tools/` 가 없다 — 필사 대상은 `pyproject.toml`
> 과 `signus/*` 22개뿐이다. 그래서 한 줄 발행과 검출 코드는 `signus/cli.py` 안에 있고,
> 인쇄물을 통해 그 장비로 들어간다. `tools/brief.py` 는 **받는 쪽(맥) 전용**이다.

### 5.1 기본 — 한 줄 (`--brief`)

```bash
signus analyze caps/capture.cplx.1000000.16t.pcm --brief
```
```
sig2 an fs1000000 iq-i16 16qam fc8000 bd100000 lk100 mer29.8 rl0.33 #vsej
```

사람용 출력을 **대체하지 않고 맨 끝에 한 줄 더** 찍는다. 이 줄만 옮기면 된다. 읽는 법:

| 토막 | 뜻 |
|---|---|
| `sig2` | 형식 버전 |
| `an` / `sv` | analyze / survey |
| `iq-i16` | 포맷-샘플타입. **lock 0 의 1순위 용의자라 항상 싣는다** |
| `fs…` `fc…` `bd…` | 샘플레이트 · 반송파 · 심볼레이트 (Hz, 정수) |
| `lk` `mer` `rl` / `h` | lock · MER · 롤오프(FSK는 변조지수) |
| `b2/5` | 버스트 5개 중 2번째 (버스트가 하나면 안 나옴) |
| `eq al fb amb pre` | 등화기 · 앨리어스보정 · baud폴백 · 앨리어싱경고 · 프리앰블동기 (해당될 때만) |
| `#vsej` | **오타 검출 코드** |

`#vsej` 는 앞의 모든 글자의 crc32 다. 받는 쪽에서 먼저 검증하므로 **숫자를 하나 잘못
옮기면 즉시 잡힌다** — 잘못된 값으로 엉뚱한 수사를 시작하는 사고를 막는다.

```bash
# 자릿수 하나가 빠진 경우
echo "sig2 an fs1000000 iq-i16 16qam fc8000 bd10000 lk100 mer29.8 rl0.33 #vsej" \
  | tools/brief.py check
# 불일치 ✗  받은 코드 #vsej, 내용으로 계산하면 #xyrs
# → 숫자의 자릿수부터 다시 봐주세요 (검출 코드 자체의 오타는 아닌 듯합니다).
```

잡는 것과 눈감는 것 (전부 실측):

- **잡는다**: 한 자리 치환, 자릿수 누락, 부호 누락, **공백이 한 칸 밀려 값이 바뀌는 것**
  (`fs1000000 16qam` → `fs10000001 6qam` 은 샘플레이트가 10배다).
- **눈감는다**: 줄 간격, 대소문자, 그리고 검출 코드의 `o/i/l` 을 `0/1/1` 로 잘못 읽은 것
  (그 세 글자는 코드 알파벳에 아예 없어서 오통과 위험이 0이다).
- 불일치가 났을 때 **검출 코드 네 글자만 한 글자 다른 경우**는 따로 알려준다 — 본문 오타와
  코드 오타의 우도비가 약 7900:1 이라 어디를 다시 볼지 갈라준다.

survey 는 신호마다 한 줄씩 (검출 코드는 맨 끝 한 번):

```
sig2 sv fs20000000 iq-i16 n4
0 fc-6200000 bd200000 lk93 qpsk
1 fc-1500000 bd400000 lk100 16qam
2 fc3099983 bd150000 lk100 msk
3 fc7400000 bd300000 lk93 8psk #7ckr
```

### 5.2 여기에 세 줄만 덧붙인다

한 줄로는 **그게 틀렸다는 걸 알 방법이 없다.** 아래 세 줄이 수사의 시작점이다.

```
기대: qpsk, 심볼레이트 32k 부근
실제: 위 한 줄
근거: 이 링크 규격서에 qpsk 32k 로 적혀 있음
```

`근거` 가 "규격서/다른 도구/성상도 모양" 중 무엇인지만 적어주면 된다. 길게 쓸 필요 없다.

### 5.3 안 보내도 되는 것

- **잘 나온 결과는 안 보내도 된다.** 틀린 것, 이상한 것만.
- 환경(파이썬·numpy 버전)은 **크래시일 때만.**
- 파일 해시·크기도 평소엔 불필요. **같은 이름의 다른 캡처를 여러 번 시험할 때만** 적는다.

### 5.4 옮길 글자가 아예 없어도 되는 경우

격리망 장비에서는 셋 다 불가능하다 (인터넷이 없다). **맥이나 ssh 보드에서 돌린 결과**라면
이쪽이 낫다 — 오타 가능성이 0이다.

1. 리포트를 `reports/` 에 파일로 남기면 세션 끝 훅이 커밋·푸시한다. 그다음엔 "reports/ 에
   올렸다"만 말하면 된다. 아래 전체 형식을 그대로 쓸 수 있다.
   ```bash
   tools/report.sh analyze caps/x.cplx.2000000.16t.pcm > reports/2026-08-01-x.txt
   ```
   (`caps/` 와 `*.iq`·`*.pcm` 은 `.gitignore` 에 있다 — **캡처 원본은 절대 원격으로 안 나간다.**
   훅에도 1MB 제동이 걸려 있어 큰 파일이 끼면 자동 커밋 자체를 멈춘다.)
2. 화면 사진을 찍어 붙이면 그대로 읽는다.

### 5.5 전체 형식 (`tools/report.sh` — 맥·보드 전용)

파일 크기·sha256·사이드카 유무·쓴 명령·환경·요약 JSON 까지 전부 나온다.
`--report` JSON 원본은 270KB(성상도·비트·스펙트럼 배열)라 못 옮기므로, 진단에 쓰이는
`detected`/`quality`/`burst`/`eq` 만 남기고 배열은 걷어낸다.

### 5.6 증상별로 딱 하나만 더

손으로 옮기는 걸 전제로, **가장 짧으면서 진단을 가르는 것 하나씩**만 골랐다.

| 증상 | 추가로 딱 하나 | 치는 양 |
|---|---|---|
| lock 은 높은데 변조가 틀렸다 | 성상도 점이 몇 덩어리로 보이는지 (예: `4덩어리 링 1개`) | 한 마디 |
| lock 이 0~30 | `--dtype` 을 바꿔 돌린 한 줄 2개 더 (§6) | 두 줄 |
| survey 가 신호를 놓쳤다 | 놓친 신호의 대략 주파수·대역폭 (예: `+2.3M 근처 200k`) | 한 마디 |
| 심볼레이트만 배수로 틀렸다 | 요약 JSON 의 `baud_conf` 값 하나 | 숫자 하나 |
| 짧은 패킷이 안 잡힌다 | 버스트 대략 길이(샘플)와 반복 주기 | 숫자 둘 |
| 크래시 | 예외 **마지막 줄**만 | 한 줄 |

스크린샷이나 파일을 줄 수 있으면 위 표는 무시하고 그걸 주는 게 낫다.

### 5.7 받으면 하는 일

1. 검출 코드부터 검증한다 (`brief.py check`). 안 맞으면 **고치기 전에 되묻는다** — 잘못 옮겨진
   숫자로 수사를 시작하는 게 제일 비싼 사고다.
2. 아는 제원으로 `signus gen` 합성 재현을 시도한다.
3. 재현되면 `tests/` 에 잠그고 고친다 → `pytest` + `sweep --tier core` 로 정상 신호가 안
   깨졌는지 확인.
4. 재현이 안 되면 그 사실을 먼저 말하고 파일이나 §5.6 의 한 가지를 요청한다.

**재현 없이 추측으로 고치지 않는다** — 이 저장소가 반복해서 당한 게 "확신에 찬 오답"이다.

## 6. 자주 막히는 곳

**lock 이 0 근처, MER 이 음수, 롤오프가 1.00** → 거의 항상 **샘플타입이 틀렸다.** i16 파일을
f32 로 읽으면 이렇게 된다:

```
모드      qpsk   (정답 16qam)
반송파    -249999.8 Hz   (정답 8000.0)
심볼레이트 104605.5 Hz   (정답 100000.0)
롤오프    1.00   lock 0.0   MER -0.9 dB
```

`--dtype i16 / f32 / i8 / u8` 을 차례로 넣어보고 lock 이 뛰는 걸 고른다. 엔디안(`--be`)과
`--bitrev` 도 같은 방식으로 확인한다.

**`need fs + fmt`** → §2. 파일명 토큰이나 `--fs/--fmt`.

**변조는 맞는데 fc 가 이상하다** → `경고: 반송파 앨리어싱 가능` 이 같이 떴는지 본다. M제곱 톤은
fs 모듈로 랩되므로 fc 는 원리적으로 fs/sym 모듈로만 결정된다. 비트는 대개 멀쩡하다.

**π/4-DQPSK 를 QPSK 로 부른다** → 설계된 동작이다. fc 가 `baud/8` 밀리지만 `--diff` 로 비트는
정확히 나온다(BER 0).

**아날로그/톤/처프로 분류됐다** → 실패가 아니라 거부다. 이것들을 성상도에 맞추면 조용한 오답이
나오기 때문에 일부러 안 한다.

**보드에서 인쇄물이 안 나온다** → 헤드리스 크롬이 없다. `apt install chromium` 하거나
`CHROME=/usr/bin/chromium .venv/bin/python tools/codebook.py all`.
