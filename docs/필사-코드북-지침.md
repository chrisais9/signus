# 필사용 코드북 · 변경분 발급 지침

손으로 따라 치며 코드를 익히기 위한 인쇄물을 만드는 규칙. 발급기는 `tools/codebook.py`.

```bash
.venv/bin/python tools/codebook.py verify   # 인쇄물 == 원본 문자 대조 (발급 전 필수)
.venv/bin/python tools/codebook.py build    # 코드북 전체  → docs/signus-코드-필사용.pdf
.venv/bin/python tools/codebook.py diff     # 변경된 곳만  → docs/signus-코드-변경분.pdf
.venv/bin/python tools/codebook.py snap     # "여기까지 필사했다" 기준점 갱신
.venv/bin/python tools/codebook.py all --snap   # 코드북+변경분 발급 후 기준점까지
```

`build`/`diff` 는 내부적으로 먼저 `verify` 를 돌리고, 한 글자라도 원본과 다르면 **발급을 중단**한다.

## 실신호 디버깅 ↔ 인쇄물 동기화 루프

실제 환경에서 실신호를 넣어 디버깅하면 코드가 계속 바뀐다. 이미 손으로 옮겨 둔 필사본을
버리지 않으려면 아래 순서를 지킨다.

1. **캡처 투입** — 광대역이면 `signus survey FILE`, 단일 신호면 `signus analyze FILE`.
   파일명에 제원 토큰이 없으면 `--fs/--fmt/--dtype[--be][--bitrev]`, RF 중심주파수는 `--rf`.
   파일명 규약과 사이드카 정책은 `README.md` §파일 규약 참조 — **분석기는 정답 사이드카를
   절대 읽지 않는다**는 규칙이 실신호에서도 그대로 유지되어야 한다.
2. **증상 기록** — `--report out.json` 으로 제원 추정치(fc·baud·롤오프·lock·EVM·SNR)를 남긴다.
   버스트가 여럿이면 `--burst N` 으로 갈아 끼워 본다.
3. **원인 좁히기** — 낮은 lock 이 곧 버그는 아니다. `README.md` §정직한 한계에 적힌
   원리적 한계(프리에코 채널, 강한 에코+QAM, 롤오프 α<0.05, OQPSK, π/4-DQPSK fc 편이)인지
   먼저 확인한다. 여기 해당하면 코드가 아니라 리포트가 정직한 것이다.
4. **고친다** → `pytest -q` 로 회귀 확인. 실신호에서 발견한 케이스는 합성으로 재현해
   `tests/` 에 남긴다 (테스트는 인쇄물에 넣지 않지만, 회귀는 반드시 테스트로 잠근다).
5. **변경분 발급** — `codebook.py diff` → `docs/signus-코드-변경분.pdf` 를 인쇄한다.
   **바뀐 파일은 통째로** 실리므로 그 파일 쪽만 새로 쓰면 된다. 초록이 달라진 줄,
   붉은 점선이 뭔가 사라진 자리다. 맨 앞 한두 줄에 변경/삭제된 파일과 쪽번호가 있다.
6. **필사본 갱신** → 다 옮겼으면 `codebook.py snap`. 이때부터 다음 diff 의 기준점이 된다.
   코드북을 통째로 다시 뽑았을 때도 `snap` 을 해서 기준점을 맞춘다.

기준점은 `.codebook/baseline/` 에 그때의 파일 사본으로 보관된다(git 무관, `.gitignore` 대상).
git 커밋 기준으로 보고 싶으면 `diff --from git:<rev>`.

## 절대 규약

깨뜨리면 필사본이 조용히 틀어진다. 발급기를 수정할 때 반드시 지킨다.

1. **테스트 코드는 넣지 않는다.** 인쇄물은 "실행에 필요한 코드"만 —
   `signus/*.py` + `signus/web/*` + `pyproject.toml`.
2. **diff 의 코드 칸에는 `+`/`−` 접두사를 붙이지 않는다.** 한 칸이라도 밀리면 인덴트가
   깨져 필사본이 망가진다. 추가 표시는 ① 줄번호 칸의 배경색·볼드, ② 코드 칸 **밖**의
   별도 부호 칸 — 두 가지로만. 코드는 언제나 보이는 그대로.
3. **바뀐 파일은 통째로 싣는다.** 훅(변경 구간)만 뽑지 않는다 — 필사본은 그 파일을 새로
   쓰는 게 부분 수정보다 안전하다. 어디가 달라졌는지는 초록 강조와 파일 띠의
   `새로 쓸 줄 24-26, 69-75` 로 찾는다.
4. **없어진 코드도, 그걸 설명하는 문구도 싣지 않는다.** 지면에는 새 파일 내용만. 사라진
   자리는 이음매의 **붉은 가로 점선**(행을 쓰지 않는 `box-shadow`)으로만 알린다.
   안내 문장을 넣지 말 것.
5. **종이를 아낀다.** 변경분에는 표지가 없다 — 제목·요약·변경/삭제 파일 목록이 12pt
   한 행씩으로 접혀 첫 쪽 위에 얹히고, 바로 아래에서 본문이 시작된다. 파일마다 새 쪽에서
   시작하지 않고 회색 띠 한 줄로 이어 붙인다 (띠가 쪽 맨 아래 3행 안에 걸리면 다음 쪽으로).
6. **verify 통과 없이 발급하지 않는다.** verify 는 세 가지를 본다:
   렉서가 문자를 잃지 않았는지 / 접힌 행을 도로 이으면 원본 줄과 같은지 /
   변경분이 그 파일의 새 내용을 1번 줄부터 끝까지 빠짐없이 덮는지.
7. **접히는 자리는 공백에 걸리면 안 된다.** 행 끝·행 머리의 공백은 눈에 보이지 않으므로
   "붙여서 입력" 규칙이 그때만 틀려진다. `wrap_line()` 이 이음매를 몇 칸 앞으로 당긴다.
8. **페이지 나눔을 CSS 에 맡기지 않는다.** 60행/쪽 고정으로 직접 계산해야 목차 쪽번호와
   "코드북 N쪽" 상호참조가 정확해진다. 행 높이를 바꾸는 스타일(여백·큰 폰트)을 넣으면
   이 계산이 깨진다.

## 레이아웃 상수의 근거

| 상수 | 값 | 왜 |
|---|---|---|
| 폰트 | Menlo 8.5pt | 한글은 Apple SD Gothic Neo 로 폴백. Menlo 자폭 = 0.604em |
| 코드 폭 | 100칸 (`WRAP_COLS`) | A4 − 좌11/우7mm − 줄번호칸 25pt = 실측 101칸. ruff `line-length=100` 과 일치해 파이썬은 거의 안 접힌다 |
| 변경분 폭 | 96칸 (`WRAP_COLS_DIFF`) | 줄번호 2칸 + 부호칸 + 여백 = 44pt 를 빼서 |
| 쪽당 행수 | 60 (`LINES_PER_PAGE`) | 12pt 행높이 × 60 = 720pt, 머리말/발치 제외 가용 741pt 안 |
| 여백 | 좌 11 / 우 7mm | 대부분의 프린터 무인쇄 여백(≈6.4mm)보다 넓다. 더 줄이면 잘린다 |

**인쇄 설정**: 배율 100%(용지에 맞춤 끄기). 축소되면 8.5pt 가 필요 이상으로 작아진다.

## 파일이 늘거나 줄면

`tools/codebook.py` 의 `SECTIONS` 를 고친다 — 섹션 제목, 파일 경로, 한 줄 설명이 목차와
쪽 머리말에 그대로 쓰인다. 순서는 알파벳이 아니라 **읽는 순서**(설정 → 입출력 → 탐지 →
DSP 코어 → 변조별 경로 → 파이프라인 → 인터페이스 → 웹)로 둔다. `SECTIONS` 에 있는 파일이
사라졌으면 발급기가 먼저 알려주고 멈춘다.
